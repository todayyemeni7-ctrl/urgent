# اليمن اليوم — غرفة الأخبار العاجلة

تطبيق ويب خفيف لفريق الأخبار وشاشة المنفذ، مع حفظ مركزي في **Supabase Postgres**، تحديثات فورية عبر **Supabase Realtime**، ومصادقة وصلاحيات على مستوى قاعدة البيانات.

## الصفحات

| الصفحة | الاستخدام | الأدوار المسموحة |
|---|---|---|
| `index.html` | شاشة الاستقبال ومتابعة الأخبار والإقرار بالاستلام أو النسخ | `admin`, `editor`, `operator`, `reader` |
| `send.html` | إرسال الأخبار والملاحظات والأشرطة وتعديلها | `admin`, `editor` |
| `archive.html` | البحث والفلترة وتصدير الأرشيف | جميع أعضاء الغرفة |

كل الصفحات تتطلب جلسة Supabase Auth وعضوية فعالة في غرفة الأخبار. زر تسجيل الخروج متاح من إعدادات الشاشة الرئيسية وشريط الأرشيف ولوحة المحررين.

## الأدوار

- **`admin`**: إدارة عضوية الغرفة وأدوارها، النشر والتعديل والتثبيت والحذف، والإقرار.
- **`editor`**: النشر والتعديل والتثبيت والإقرار؛ لا يدير العضوية ولا يحذف السجلات.
- **`operator`**: مشاهدة الأخبار وتسجيل الاستلام/النسخ من شاشة المنفذ.
- **`reader`**: مشاهدة وقراءة فقط.

تُفرض الصلاحيات في PostgreSQL عبر RLS ودوال RPC، ولا تعتمد على إخفاء الأزرار في المتصفح وحده.

## إضافة عضو أو تغيير دوره

1. من رابط **إدارة حسابات Supabase** في لوحة المحررين، أنشئ حساباً في **Auth Users** أو أرسل دعوة إليه. يجب أن يكون الحساب موجوداً أولاً في Supabase Auth.
2. سجّل الدخول إلى `send.html` بحساب `admin`.
3. افتح **الإعدادات ← حسابك وصلاحيات الفريق**، وأدخل بريد المستخدم واسمه الظاهر والدور المطلوب ثم اضغط «إسناد الدور / تحديثه».
4. يمكن إزالة العضو من الغرفة من القائمة نفسها. لا تسمح قاعدة البيانات بإزالة آخر مسؤول أو تغيير دور حساب المسؤول الحالي إلى دور أدنى.

لا تُدخل كلمات المرور في لوحة الإدارة، ولا ترسلها إلى أي شخص. عضوية الغرفة منفصلة عن إنشاء حساب Supabase نفسه.

## Supabase والبيانات

- عنوان المشروع ومعرّف الغرفة ومفتاح **Publishable** العام موجودة في `config.js`. المفتاح العام ليس بديلاً عن سياسات RLS.
- لا تضع `sb_secret` أو `service_role` في المتصفح أو Git أو إعدادات Vercel العامة.
- الجداول الأساسية: `rooms` و`room_members` و`urgent_items`.
- الأخبار والملاحظات والأشرطة وإشارات الإقرار والتثبيت تُحفظ في Postgres. لا يوجد حذف تلقائي بسبب العمر (`maxAgeDays: 0`).
- عمليات الحفظ والإقرار والتثبيت وإدارة العضوية تمر عبر دوال RPC محددة تتحقق من دور المستخدم.
- Realtime يستخدم قنوات خاصة بغرفة UUID؛ يُسمح لكل عضو بمشاهدة أحداث الغرفة والحضور، أما البث العام من العميل فمحصور بـ`admin` و`editor`.
- كل هجرة محفوظة تحت `supabase/migrations/` بأرقام الإصدارات المسجلة في Supabase. مشروع Supabase المرتبط بهذه النسخة طُبّقت عليه الهجرات حتى `20261013181429_serialize_member_role_changes`.

## الأرشيف والسرعة

- تُحمّل شاشة الاستقبال آخر **400** سجل كحد أقصى، ولوحة المحررين آخر **300**؛ الأرشيف صفحة منفصلة كي لا تثقل الشاشة الرئيسية.
- يبدأ الأرشيف بتحميل آخر **1,000** سجل، ثم يحمّل دفعات من **500** عند الطلب. حد عرض المتصفح الحالي **10,000** سجل لكل جلسة أرشيف؛ البيانات الأقدم تبقى محفوظة في قاعدة البيانات.
- تصدير JSON/النص يشمل السجلات المحمّلة في جلسة الأرشيف الحالية. لنسخة كاملة عند تجاوز حد العرض، استخدم أدوات تصدير قاعدة البيانات من Supabase.
- الأخبار لا تُقرأ أو تُخزّن في `localStorage`؛ Supabase هو مصدر الحقيقة، ولا تظهر بقايا محلية قبل تسجيل الدخول.
- ملف SDK المحلي `vendor/supabase.min.js` يُحمّل عند الحاجة فقط، بدلاً من تحميل ناقل MQTT القديم. حفظ/تعديل الخبر يمر بطلب RPC واحد. مؤشر الاتصال يعرض Supabase Realtime وزمن استجابة API التقريبي.
- خدمة التطبيق `sw.js` وإصدارات الملفات محدثة إلى `4.17.1` لتجاوز ملفات الكاش القديمة.

## النشر

المشروع صفحات ثابتة؛ يمكن ربط المستودع الخاص `todayyemeni7-ctrl/urgent` بـVercel دون خادم تطبيق إضافي. لا يلزم وضع مفتاح سري في متغيرات الواجهة. بعد النشر، جرّب تسجيل الدخول من الهاتف وتأكد من نجاح ظهور اتصال Realtime وزمن الاستجابة.

## حماية المفاتيح

يستخدم التطبيق المفتاح العام القابل للنشر فقط. إذا سبق أن شاركت مفتاحاً من نوع `sb_secret`، اعتبره مكشوفاً ودوّره/ألغِه من **Supabase → Project Settings → API Keys**؛ لا تستخدمه داخل `config.js` أو ترسله في المحادثات.
