# اليمن اليوم — غرفة الأخبار العاجلة

تطبيق ويب خفيف لفريق الأخبار وشاشة المنفذ، مع حفظ مركزي في **Supabase Postgres**، تحديثات فورية عبر **Supabase Realtime**، ومصادقة وصلاحيات على مستوى قاعدة البيانات.

## الصفحات

| الصفحة | الاستخدام | الأدوار المسموحة |
|---|---|---|
| `index.html` | شاشة الاستقبال ومتابعة الأخبار والإقرار بالاستلام أو النسخ والرد على الملاحظات؛ لها جلسة مستقلة لكل جهاز | `admin`, `editor`, `operator`, `reader` |
| `send.html` | إرسال الأخبار والملاحظات والأشرطة وتعديلها واستقبال ردود المنفذ | `admin`, `editor` |
| `archive.html` | البحث والفلترة وتصدير الأرشيف | جميع أعضاء الغرفة |
| `public.html` | الصفحة العامة: عرض الأخبار العاجلة فقط بلا تسجيل دخول، مع إشعارات المتصفح وتنبيه صوتي عند وصول خبر | الجميع — بلا حساب |

كل الصفحات ما عدا `public.html` تتطلب جلسة Supabase Auth وعضوية فعالة في غرفة الأخبار؛ الصفحة العامة تقرأ عبر دالة `urgent_public_news` التي لا تعيد إلا الأخبار العاجلة غير المحذوفة (لا ملاحظات، لا أشرطة، لا بيانات إقرار أو نسخ). شاشة الاستقبال لها جلسة منفصلة على كل جهاز؛ عند أول فتح يسجّل المستخدم باسم حساب الشاشة وكلمته، ثم تبقى الجلسة على ذلك الجهاز حتى تسجيل الخروج. لا توجد أزرار تنقل مباشر بين شاشة الاستقبال ولوحة المحررين.

## الأدوار

- **`admin`**: إدارة عضوية الغرفة وأدوارها، النشر والتعديل والتثبيت والحذف، والإقرار. وحده من تظهر له في شاشة الاستقبال خيارات الإشعارات الصوتية والمرئية.
- **`editor`**: النشر والتعديل والتثبيت والإقرار؛ لا يدير العضوية ولا يحذف السجلات.
- **`operator`**: مشاهدة الأخبار وتسجيل الاستلام/النسخ من شاشة المنفذ، والرد على الملاحظات (يصل الرد للمحرر مع تنبيه).
- **`reader`**: قراءة الأخبار العاجلة فقط — لا تظهر له الملاحظات ولا الشريط ولا تفاصيل النسخ.

تُفرض الصلاحيات في PostgreSQL عبر RLS ودوال RPC، ولا تعتمد على إخفاء الأزرار في المتصفح وحده.

## إضافة عضو أو تغيير دوره

1. سجّل الدخول إلى `send.html` بحساب `admin`، ثم افتح **الإعدادات ← حسابك وصلاحيات الفريق**.
2. أضف اسم المستخدم وكلمة المرور والاسم الظاهر، واختر أحد الأدوار الأربعة. افتراضياً يبدأ العضو بدور `reader` ولا يرى الشريط حتى تمنحه هذا الإذن.
3. غيّر الدور أو فعّل/أوقف **رؤية الشريط** من صف العضو. يمكن من الصف نفسه تعيين كلمة مرور جديدة أو إزالة العضو من الغرفة.
4. لحساب شاشة التنفيذ، اختر الدور `operator` من نموذج إضافة العضو نفسه وحدد صلاحية رؤية الشريط عند الحاجة؛ لا يوجد نموذج منفصل لإنشاء حساب منفذ.

تُنشأ حسابات الأسماء داخلياً عبر Edge Function محمية بجلسة المسؤول؛ لا يلزم بريد حقيقي للمستخدم، ولا تصل مفاتيح الإدارة إلى المتصفح. بريد حساب المالك الحالي يبقى صالحاً لتسجيل الدخول. كلمات المرور لا تُعرض بعد حفظها ولا تُخزّن كنص صريح في المشروع.

## Supabase والبيانات

- عنوان المشروع ومعرّف الغرفة ومفتاح **Publishable** العام موجودة في `config.js`. المفتاح العام ليس بديلاً عن سياسات RLS.
- لا تضع `sb_secret` أو `service_role` في المتصفح أو Git أو إعدادات Vercel العامة.
- الجداول الأساسية: `rooms` و`room_members` و`urgent_items`.
- الأخبار والملاحظات والأشرطة وإشارات الإقرار والتثبيت تُحفظ في Postgres. لا يوجد حذف تلقائي بسبب العمر (`maxAgeDays: 0`).
- عمليات الحفظ والإقرار والتثبيت وإدارة العضوية تمر عبر دوال RPC محددة تتحقق من دور المستخدم.
- Realtime يستخدم قناة خاصة للغرفة، وقناة منفصلة للأشرطة لا يقرأها إلا العضو الذي يملك `can_view_bar`. سياسات RLS تطبق الإذن أيضاً على سجلات Postgres وعمليات الإقرار/التثبيت، وليس على الواجهة فقط.
- هجرات القاعدة محفوظة تحت `supabase/migrations/`. تشمل `usernames_and_bar_visibility` و`reader_news_only` و`note_replies_and_public_news`؛ وظيفة الإدارة `manage-users` تتطلب JWT (`verify_jwt = true`) وتستخدم أسرار Supabase على الخادم فقط.

## الأرشيف والسرعة

- تُحمّل شاشة الاستقبال آخر **400** سجل كحد أقصى، ولوحة المحررين آخر **300**؛ الأرشيف صفحة منفصلة كي لا تثقل الشاشة الرئيسية.
- يبدأ الأرشيف بتحميل آخر **1,000** سجل، ثم يحمّل دفعات من **500** عند الطلب. حد عرض المتصفح الحالي **10,000** سجل لكل جلسة أرشيف؛ البيانات الأقدم تبقى محفوظة في قاعدة البيانات.
- تصدير JSON/النص يشمل السجلات المحمّلة في جلسة الأرشيف الحالية. لنسخة كاملة عند تجاوز حد العرض، استخدم أدوات تصدير قاعدة البيانات من Supabase.
- يستطيع المالك **استيراد** أخبار وملاحظات من نظام قديم (ملف JSON: `[..]` أو `{items:[..]}`) من لوحة المحررين ← الإعدادات ← «استيراد الأرشيف من النظام السابق»؛ تُحفظ العناصر بتوقيتها الأصلي وتُعلَّم تلقائياً كأرشيف منتهٍ ولا يتكرر إدخالها عند إعادة الاستيراد. أي عنصر يصل البث المباشر بتوقيت أقدم من 10 دقائق (استيراد أو لحاق مزامنة) يُعرض بصمت دون تشغيل الإنذار الصوتي أو إشعارات سطح المكتب.
- الأخبار لا تُقرأ أو تُخزّن في `localStorage`؛ Supabase هو مصدر الحقيقة، ولا تظهر بقايا محلية قبل تسجيل الدخول.
- ملف SDK المحلي `vendor/supabase.min.js` يُحمّل عند الحاجة فقط، بدلاً من تحميل ناقل MQTT القديم. حفظ/تعديل الخبر يمر بطلب RPC واحد. مؤشر الاتصال يعرض Supabase Realtime وزمن استجابة API التقريبي.
- خدمة التطبيق `sw.js` وإصدارات الملفات محدثة إلى `4.18.37` لإبطال كاش الأجهزة القديمة. يستقبل التطبيق INSERT/UPDATE عبر Broadcast وPostgres Changes مع مزامنة استدراكية كل 5 ثوانٍ، وتبقى القراءة محكومة بـRLS. القارئ يرى الأخبار فقط؛ تُستبعد أنواع الملاحظات والأشرطة وحقول الإقرار من استعلاماته وأحداثه، كما تُحجب تفاصيل النسخ عن واجهة الأرشيف وتصديره. أحداث DELETE تبقى على Broadcast الخاص لأن Supabase لا يطبق RLS عليها في Postgres Changes. يمنع RPC إقرار «وصل» المتأخر من استبدال حالة «نُسخ» أو «استلم».
- يبقى رابط الأرشيف في نهاية تدفق الصفحة، لا مثبتاً أثناء التمرير. أرشيف شاشة الاستقبال يستخدم جلسة الشاشة نفسها دون نسخها إلى مخزن جلسة المحررين؛ وتظل تبويبات وإحصاءات الشريط مخفية حتى التحقق من `can_view_bar`. تظهر أيقونة الانتقال بين المحرر والاستقبال للأدوار المسموحة فقط. حضور الأعضاء يعتمد على الانضمام/المغادرة الفعلية للقناة دون نبضات متكررة، وأثناء استعادة الجلسة يظهر الشعار بدلاً من نموذج الدخول المؤقت.
- يتضمن `sw.js` مستقبلاً لأحداث Web Push، لكن مشروع Supabase الحالي لا يملك مرسلاً مفعّلاً أو جدول اشتراكات لهذه الإشعارات؛ لذلك لا تصل إشعارات عند إغلاق الصفحة لمجرد وجود Realtime أو تسجيل Service Worker. يتطلب ذلك مرسلاً خادمياً (مثلاً Edge Function) واشتراكات Push ومفاتيح VAPID محفوظة كأسرار خادمية؛ لا توجد خانة إعداد خادم غير مفعّلة في الواجهة الحالية.

## النشر

المشروع صفحات ثابتة؛ يمكن ربط المستودع الخاص `todayyemeni7-ctrl/urgent` بـVercel دون خادم تطبيق إضافي. لا يلزم وضع مفتاح سري في متغيرات الواجهة. بعد النشر، جرّب تسجيل الدخول من الهاتف وتأكد من نجاح ظهور اتصال Realtime وزمن الاستجابة.

## حماية المفاتيح

يستخدم التطبيق المفتاح العام القابل للنشر فقط. إذا سبق أن شاركت مفتاحاً من نوع `sb_secret`، اعتبره مكشوفاً ودوّره/ألغِه من **Supabase → Project Settings → API Keys**؛ لا تستخدمه داخل `config.js` أو ترسله في المحادثات.
